## The big idea

> The designer is no longer making choices about a single, final object, but creating a matrix encompassing an entire population of possible designs.

This is what changes when you design with code. The deliverable is the system; the images are evidence of the system.

## One structure

Every computational system shares the same shape:

**Input** (parameters, data, variables) → **Process** (algorithm, procedure, operation tree) → **Output** (design)

What separates the three paradigms is a single question: **how determined is the output?**

| | Algorithmic / Procedural | Parametric | Generative |
|---|---|---|---|
| **Process** | A fixed sequence of operations | Relationships between inputs and form | A rule applied to its own output, repeatedly |
| **You define** | The steps | The rules of variation | The rule + the starting state |
| **Output is** | One expected result | A family — you know the range, not each member | Unknown, within a spectrum you set |
| **Module** | 0 | 1–3 | Final |

### A note on "partially expected"

A parametric system is fully deterministic — the same inputs always produce the same output. So why is the output only *partially* expected? Because you are authoring a **space**, not a result. You know its range, not every member of it. That is the point.

## 01 — Procedural

Sol LeWitt's wall drawings are the clearest case: the work is a written instruction, and the person who executes it is not the person who wrote it. LeWitt often never touched the wall.

A machine reading a toolpath does exactly this. So does a Boolean history.

**An instruction:**

```
1.  Place twenty points at random on the sheet.
2.  Connect each point to its two nearest
    neighbours with a straight line.
```

Two lines, and it produces a drawing nobody composed. Ask what is still undecided: how random is random? How big is the sheet? Do lines cross?

Every execution differs — and for LeWitt that variance *was* the work.

## 02 — Parametric

The author defines the process and its flexibility.

- Same inputs in → same result out. Always.
- Change one input → the whole system responds.
- Non-destructive → every step stays editable.

## 03 — Generative

The system feeds itself. Every generative system is the same three-step loop, run over and over:

**state → rule → next state → *(the output becomes the input)***

Families: growth · agents · cellular automata · relaxation and packing.

Try [Conway's Game of Life](https://copy.sh/life/). Four rules, no design, and it produces things nobody specified.
