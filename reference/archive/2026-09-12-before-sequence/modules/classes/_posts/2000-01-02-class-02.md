## Tutorial 0.1 — the logic

Not the buttons. The four things a graph actually does:

1. **A graph is a chain of operations.** Each node takes something in, does one thing, passes it on.
2. **Data flows left to right.** If a result is wrong, walk backwards until it stops being wrong.
3. **Geometry is an output, not a thing.** Nothing is "made". The graph describes how to make it, every time.
4. **Every input stays live.** Change a number at the start and everything downstream recomputes.

## Why non-destructive

Same job both times: make the sphere bigger.

**Destructive** — cube, sphere, one mesh. The operations were discarded. The sphere no longer exists as anything you can edit. To change it you rebuild from scratch.

**Non-destructive** — cube and sphere are still live nodes feeding a subtract. Change the radius and everything downstream recomputes.

## Three Booleans

| | |
|---|---|
| **Union** | A + B |
| **Difference** | A − B |
| **Intersection** | A ∩ B |

Order matters. `A − B` is not `B − A`. Your procedure must make the order unambiguous.

## Transformations are arithmetic

Three operations on a coordinate. Nothing more mysterious than that.

| | Is | The maths | Example |
|---|---|---|---|
| **Move** | addition | `x' = x + dx` | (2, 1) + (3, 0) → (5, 1) |
| **Scale** | multiplication | `x' = x × f` | (2, 1) × 2 → (4, 2) |
| **Rotate** | mixing x and y | `x' = x·cosθ − y·sinθ`<br>`y' = x·sinθ + y·cosθ` | (1, 0) rot 90° → (0, 1) |

**Move and scale treat each coordinate on its own. Rotation is the only one where x and y have to talk to each other** — which is why it needs sine and cosine, and why rotating about the wrong point is the classic mistake.

## The notation

Write the procedure as pseudocode. Formal enough to be unambiguous, plain enough to read aloud.

```
PRIMITIVES          TRANSFORMS               BOOLEANS
box(x, y, z)        move(s, x, y, z)         union(a, b)
cylinder(r, h)      rotate(s, axis, deg)     subtract(a, b)
sphere(r)           scale(s, factor)         intersect(a, b)
cone(r, h)
```

**Three rules**

- Every shape is created **centred on the origin (0, 0, 0)**. Move it from there.
- **Units are abstract.** No millimetres, no metres — 3 units, half the width.
- **Every step assigns a name**, so the order of a subtraction is never in doubt.

This is real: [OpenSCAD](https://openscad.org/) is a working language built on exactly these operations.

### Worked example

```
base   = box(6, 4, 3)
tower  = box(2, 2, 6)
tower  = move(tower, 2, 0, 3)
void   = cylinder(r=1, h=5)
void   = move(void, -1.5, 0, 0)

mass   = union(base, tower)
result = subtract(mass, void)
```

What this fixes:

- **Order** — `subtract(mass, void)` can only mean one thing.
- **Position** — every shape starts at the origin, so a move is the whole story.
- **Reuse** — a named step can be referred to later; `mass` is used, not rebuilt.
- **Reading** — anyone can execute it. That is the test at Class 5.

## Precedent — the massing diagram

One drawing per operation. The sequence is the argument.

What makes it work:

- One operation per frame. Never two.
- The same viewpoint every frame, so the change is the only thing moving.
- The moved or removed part is marked — colour, arrow, ghost.
- It reads left to right without a caption.

## Choosing your object

- **Orthogonal massing** — boxes, slabs, stacked volumes. Right angles.
- **No complex curves** — if you cannot get there with primitives, it is the wrong building.
- **5–10 clear moves** — too simple is boring; too complex will not resolve in five Booleans.
