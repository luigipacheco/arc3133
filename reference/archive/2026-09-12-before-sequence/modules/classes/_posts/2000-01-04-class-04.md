Module 0 is finished. The ground has changed.

| Procedural — done | Parametric — now |
|---|---|
| A fixed sequence of operations. You defined the steps. One expected result. | Relationships between inputs and form. You define the rules of variation. A family — you know the range, not each member. |

**An array on its own is still procedural** — repeat this N times. It becomes parametric the moment a parameter governs how the copies differ.

## An array is a list of positions

Not a command that duplicates things. A list you compute, then place geometry at.

```
i = 0   →   p = start
i = 1   →   p = start + step
i = 2   →   p = start + 2 × step
i = 3   →   p = start + 3 × step

p[i] = start + i × step
```

You already know this. **Move is addition. An array is move, repeated, with the amount driven by the index.**

The index is the only new idea: a counter that tells each copy how far along the sequence it is — and therefore how different it should be. Without it every copy is identical, because nothing distinguishes one from another.

## Four arrays

| | |
|---|---|
| **Linear** | `p[i] = p₀ + i·d` |
| **Grid** | `p[i][j] = p₀ + (i·dx, j·dy)` |
| **Hexagonal** | offset odd rows by `dx/2` |
| **On curve** | `p[i] = curve at t = i/n` |

A grid is a **list of lists** — two counters instead of one. Hold that thought; it returns in Module 3 as a panel field.

## Repetition is not the point

The same grid, twice. One is a pattern; the other is a system.

- **Repetition** — every element identical. The index is generated and then ignored. *Procedural.*
- **Variation** — size driven by the index. The same list, now doing work. *Parametric.*

*1.1 requires variation. A field of identical elements does not meet the assignment.*

## Arrays in architecture

Screens, façades, structure, aggregation. Look for the rule, not the image. For each precedent, ask three questions:

1. What is the module?
2. What generates the positions?
3. What varies across the field, and what drives it?
