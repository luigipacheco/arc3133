### Slide 3

THREE PARADIGMS
Each one a strict extension of the one before it.
01   PROCEDURAL
Form as a fixed sequence of operations. You define the steps.
Output is expected.
02   PARAMETRIC
Relationships between inputs and form. You define the rules of variation.
Output is a family — you know the range, not each member.
03   GENERATIVE
A rule applied to its own output, repeatedly. You define the rule and the starting state.
Output is unknown, within a spectrum you set.
A procedure is a fixed recipe. A parametric system is a recipe with dials. A generative system reads its own output and decides what to do next.

### Slide 11

THE NOTATION
Write the procedure as pseudocode. Formal enough to be unambiguous, plain enough to read aloud.



PRIMITIVES
box(x, y, z)
cylinder(r, h)
sphere(r)
cone(r, h)



TRANSFORMS
move(s, x, y, z)
rotate(s, axis, deg)
scale(s, factor)



BOOLEANS
union(a, b)
subtract(a, b)
intersect(a, b)


THREE RULES

Every shape is created centred on the origin (0, 0, 0). Move it from there.

Units are abstract. No millimetres, no metres — 3 units, half the width.

Every step assigns a name, so the order of a subtraction is never in doubt.
This is real: OpenSCAD is a working language built on exactly these operations.


### Slide 12

WORKED EXAMPLE



PROCEDURE
base   = box(6, 4, 3)
tower  = box(2, 2, 6)
tower  = move(tower, 2, 0, 3)
void   = cylinder(r=1, h=5)
void   = move(void, -1.5, 0, 0)

mass   = union(base, tower)
result = subtract(mass, void)


WHAT THIS FIXES
ORDER
subtract(mass, void) can only mean one thing.
POSITION
Every shape starts at the origin, so a move is the whole story.
REUSE
A named step can be referred to later — mass is used, not rebuilt.
READING
Anyone can execute it. That is the test at Class 5.

### Slide 7

TWO WAYS TO REPEAT
Worth being precise about, because they look alike and are not.
EXPLICIT ITERATION
A Repeat Zone runs a body once per step, in order, carrying a value forward.

PER-ELEMENT EVALUATION
The other kind is evaluated across every element at once. There is no order and no carry.
 
It is faster and it is usually what you want — but nothing on screen tells you a loop happened, which is exactly why we built the explicit one first.
NEXT WEEK THIS GETS A NAME. FOR NOW: ONE CARRIES A VALUE FORWARD, THE OTHER DOES NOT.

### Slide 7

TWO WAYS TO REPEAT
Worth being precise about, because they look alike and are not.
EXPLICIT ITERATION
A Repeat Zone runs a body once per step, in order, carrying a value forward.
 
Use it when step n depends on step n−1 — and when you want to watch the loop happen.
PER-ELEMENT EVALUATION
The other kind is evaluated across every element at once. There is no order and no carry.
 
It is faster and it is usually what you want — but nothing on screen tells you a loop happened, which is exactly why we built the explicit one first.
NEXT WEEK THIS GETS A NAME. FOR NOW: ONE CARRIES A VALUE FORWARD, THE OTHER DOES NOT.

### Slide 5

REMAP, AND SAY WHERE YOU CLAMPED
Distance comes out in model units. Your property needs a specific range.
THE OPERATION
t   = (d − dmin) / (dmax − dmin)
out = outmin + t × (outmax − outmin)
 
d    0 … 8.4 units      ← source
out  0.1 … 1.0 radius   ← target
SUBTRACT. DIVIDE. MULTIPLY. ADD.
Nothing here is new — it is the arithmetic from Week 2 applied to a distance instead of a coordinate.
 
Clamping is a decision, not a safety net. Decide what happens past the end of your range and say so.
P2b REQUIRES SOURCE AND TARGET RANGES, CLAMPING AND FALLOFF STATED ON THE SHEET.
